⏸Pausa aquiPor que o cupom não vai numa máquina virtual ligada o dia todo?ver a resposta

Porque ele trabalha uns segundos por pedido. A máquina ficaria quase o dia inteiro parada, e você pagaria cada hora. No serverless, um evento acorda a função, e você paga só o tempo em que ela rodou.

C2–C5 · conceitos

O que a prova quer que você saiba

C2

IaaS: infraestrutura como serviço

A categoria mais flexível, com o máximo de controle. Você aluga o hardware num datacenter da nuvem, e o que faz com ele é com você.

  • O provedor cuida: do hardware, da conexão com a internet e da segurança física.
  • Você cuida: do sistema operacional (instalar, configurar, atualizar), da rede, do banco de dados e do armazenamento.
  • Cenários: levar o sistema como está (lift-and-shift) e ambientes de teste e desenvolvimento.

Fonte: Microsoft Learn, Descrever a infraestrutura como serviço, consultado em 12/11/2026.

No Azure: as Máquinas Virtuais do Azure. Como é na AWS: o Amazon EC2.

C3

PaaS: plataforma como serviço

O meio-termo entre alugar o datacenter (IaaS) e pagar a solução pronta (SaaS).

  • O provedor cuida: da infraestrutura e também do sistema operacional, do middleware, das ferramentas de desenvolvimento e de análise. Nada de licença nem de atualização do sistema e do banco.
  • Você cuida: do código do aplicativo, dos dados e de quem acessa.
  • Cenários: uma estrutura pronta para os programadores criarem aplicativos, e análise de dados (business intelligence).

Fontes: Microsoft Learn, Descrever a plataforma como serviço, Descrever as opções de hospedagem de aplicativos e O que é o Banco de Dados SQL do Azure?, consultados em 12/11/2026.

No Azure: o Serviço de Aplicativo (App Service) e o Banco de Dados SQL do Azure. Como é na AWS: o AWS Elastic Beanstalk.

C4

SaaS: software como serviço

O modelo mais completo: você aluga ou usa um aplicativo pronto. É o menos flexível, mas o mais fácil de começar, e pede menos conhecimento técnico.

  • O provedor cuida: de quase tudo, da infraestrutura às atualizações do aplicativo.
  • Você cuida: dos seus dados, das contas e de quem acessa, e dos aparelhos que entram.
  • Cenários: e-mail e mensagens, aplicativos de produtividade, controle de finanças e despesas.

Fonte: Microsoft Learn, Descrever o software como serviço, consultado em 12/11/2026.

Exemplo: o Microsoft 365 (Outlook, Word, Teams). Como é na AWS: a AWS também agrupa os serviços em IaaS, PaaS e SaaS (AWS, Types of cloud computing, consultado em 12/11/2026).

C5

Serverless: a computação sem servidor

O provedor cuida da infraestrutura, da escala e da manutenção. Você só escreve o código, e ele roda quando um evento acontece.

  • Um evento acorda a função: um pedido novo, um horário marcado, uma mensagem de outro serviço.
  • Trabalho curto: o ideal é terminar em segundos. Acabou, os recursos são liberados.
  • Paga pelo que rodou: o Azure cobra o tempo de execução, não a máquina parada esperando.
  • Escala sozinha, conforme a procura.

No Cerrado Delivery: o cupom de cada compra.

Fontes: Microsoft Learn, Descrever o Azure Functions e Microsoft Azure, O que é computação sem servidor?, consultados em 12/11/2026.

No Azure: o Azure Functions. Como é na AWS: o AWS Lambda (AWS Lambda, consultado em 12/11/2026).

P1 · pegadinha de prova

Serverless tem servidor

Dois nomes que enganam muita gente.

ConfusãoO certoA pista na questão
"Serverless não tem servidor"Tem, e muitos. Você é que não cuida deles: o provedor cuida da infraestrutura e da escala."Orientado a eventos", "paga só pela execução", "sem gerenciar servidores".
PaaS × SaaSNo PaaS, o código é seu, e a plataforma é do provedor. No SaaS, até o aplicativo é do provedor."Desenvolvedores", "implantar o aplicativo" é PaaS; "usar o aplicativo pronto" é SaaS.
IaaS × PaaSNo IaaS, o sistema operacional é seu. No PaaS, não."Mais controle", "configurar o sistema operacional" é IaaS.
⏸Pausa aquiUma equipe quer publicar o site sem cuidar de atualização do sistema operacional, mas o código é dela. Qual modelo?ver a resposta

PaaS, como o Serviço de Aplicativo do Azure. O código é da equipe; o sistema operacional e as atualizações ficam com o provedor.

Teste:
  1. Uma empresa usa o Outlook do Microsoft 365. Qual modelo? SaaS.
  2. Um código redimensiona as fotos quando alguém envia uma. Qual modelo? Serverless: roda por evento.

T1

Qual modelo?

Agora é com você:

  1. Uma empresa leva os servidores do escritório para a nuvem sem mudar nada.
  2. Um escritório passa a usar um sistema de folha de pagamento pronto, no navegador.
  3. Os programadores publicam a API sem cuidar do sistema operacional nem das atualizações.
  4. Quando uma nota fiscal chega, um código lê os dados em segundos e para.
  5. A equipe precisa instalar um sistema antigo que só roda numa versão específica do Windows Server.
  6. Uma escola troca o servidor de e-mail próprio pelo Outlook do Microsoft 365.
